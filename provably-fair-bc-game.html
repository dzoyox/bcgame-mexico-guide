Provably Fair en BC.GAME: qué verifica realmente

Es un método criptográfico para comprobar que el resultado de una ronda coincide con datos comprometidos previamente. No convierte un juego en rentable ni elimina la ventaja de la casa.

Revisado el 6 de octubre de 2026.

En esta guía
  • Server seed, client seed y nonce
  • Cómo verificar una ronda
  • Qué no demuestra

Las cuatro piezas

  1. Server seed: un valor secreto generado por el servidor. Antes de jugar se publica su hash, como compromiso previo.
  2. Client seed: un valor asociado al jugador que interviene en el cálculo.
  3. Nonce: un contador que cambia entre rondas para producir resultados distintos con las mismas semillas.
  4. Resultado: el algoritmo combina esos datos y los transforma en el valor usado por el juego.

Cómo comprobar una ronda

  1. Guarda el hash del server seed mostrado antes de la ronda.
  2. Cuando el server seed se revele o rote, calcula su hash.
  3. Confirma que coincide con el compromiso publicado anteriormente.
  4. Introduce server seed, client seed y nonce en el verificador correspondiente al juego.
  5. Comprueba que el resultado reproducido coincide con el historial.

El algoritmo puede variar según el juego. No asumas que una fórmula de Crash sirve para Dice, Limbo u otro título.

Qué no demuestra

  • No garantiza una victoria ni una devolución concreta.
  • No elimina el house edge.
  • No demuestra por sí solo la solvencia, la licencia o la rapidez de los retiros.
  • No permite predecir la siguiente ronda.
Regla útil: usa el verificador oficial o uno cuyo código puedas revisar. Nunca introduzcas contraseñas, claves privadas ni frases semilla en una herramienta de verificación.
